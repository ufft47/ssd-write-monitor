## 監控與量測

- **把「未緩衝 I/O」單獨量出來。** 目前覆蓋率只有 3.2%，最大宗是未緩衝 I/O 與核心內部寫入。
  如果能在 ETW 之外補一條來源（例如 IRP 層或 `FileIo` 的 unbuffered 旗標），歸因率可能大幅改善。
- **用 USN 變更日誌交叉驗證歸因。** 需管理員（`fsutil usn readjournal C:`）。
  可以回答「ETW 說某程式寫了 X，USN 是否也看到同樣的檔案變更」。
- **每小時報告加一欄「與前一週同日比較」。** 現在只有當日趨勢，看不出「今天特別髒是因為什麼」。
- **儀表板加「Top 檔案的歷史曲線」**（例如 `WebCacheV01.dat` 每天固定寫多少），
  用來判斷某個檔案是「正常churn」還是「異常成長」。
- **把 `avg-migration.json` 這類「狀態檔」統一格式**，讓儀表板可以一頁列出所有進行中的觀察期。

## 資料治理

- **歸因 CSV 加一欄「可信度」**（ok / dir / missing / device），讓所有下游不必各自重算。
  現在儀表板、`clean-attrib.ps1`、`disk-report.ps1` 三處各有一套規則，容易不同步。
- **`hours-summary.log` 的 `cover` 欄位定義要統一**：目前每小時的分子含可疑列，
  與儀表板的算法不一致。
- **建立「資料保留策略」**：`data/attrib` 一天一個 CSV，長期會累積。要不要壓縮或只留摘要？
